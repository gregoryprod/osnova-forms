# OS.NOVA Forms

Небольшой отдельный Rails API: анкета osnova-mind.ru → сохранение в зашифрованной SQLite → очередь → «Неразобранное» amoCRM.
Сайт остаётся статическим. Mini App `app.osnova-mind.ru` не изменяется.

## Статус

Код подготовлен для администратора. На VPS не установлен, сайт не переключён. В amoCRM сделаны только запросы чтения: новых сущностей эта разработка пока не создавала. Сквозная приёмка живой CRM и браузерный тест остаются обязательными.

## Запуск и тесты

Ruby 3.4.11, Rails 8.1.4, SQLite, Solid Queue; Node нужен только для JS-тестов.

```sh
bundle install
bin/rails db:prepare
bin/ci
```

Доставка использует переменные из `.env.example`. Приложение само `.env` не загружает: переменные задаёт оболочка или systemd EnvironmentFile.
Production: `bin/rails db:prepare`, затем `bundle exec puma -C config/puma.rb`.
API слушает только 127.0.0.1:3100. Базы в STORAGE_PATH должны переживать смену релиза.

## Контракт

POST /v1/intake, JSON, Origin https://osnova-mind.ru или https://www.osnova-mind.ru.
answers: семь {id:q1…q7, index, text}; name; contact; consent:true; client_submission_id:UUIDv4;
version:1; form:diagnostic-intake; page:URL сайта; website:пустая ловушка; referrer, utm опциональны.
201 означает сохранение, а не подтверждение amoCRM. Повтор UUID с тем же содержимым возвращает прежний ID, изменённое содержимое — 409.
Лимит 5 POST/минуту/IP в одном Puma-процессе. При масштабировании заменить MemoryStore общим хранилищем лимитов.
Origin не защищает от клиентов, подделывающих заголовки; это ограничение браузерного доступа вместе с лимитом, валидацией и ловушкой.

Ответы идут в существующие поля КОНТАКТА по enum_id, UTM — в штатные поля сделки. Индекс не заменяет проверку текста: неизвестный ответ сохраняется в сводке и вызывает уведомление. Контакт в неразобранном создаётся вместе с заявкой; объединение дублей при принятии выполняется средствами CRM/менеджером, автоматическая дедупликация не заявляется.
Дата согласия, URL и SHA256 версий документов фиксируются при приёме и передаются в примечание. При изменении документов обновить config/legal_versions.json до выкладки соответствующего сайта.

## Надёжность

Сначала сохранение, затем постановка задачи; ежеминутный dispatcher подбирает неотправленные строки даже после сбоя очереди.
401/403/429 повторяются с паузой до 20 попыток; ошибочные данные 400 → failed. Таймаут/5xx при создании может означать, что amoCRM уже создала заявку: такая строка становится uncertain и требует сверки. Слепого повторного создания нет.
ID сущностей CRM сохраняются до добавления примечания. Если сбоит примечание, повторяется оно, без новой сделки; после неоднозначного ответа примечание может продублироваться.
Статусы pending/failed/uncertain видны через `bin/rails submissions:status`; тела анкет команда не выводит.

Telegram-бот для ошибок настраивается через ALERT_BOT_TOKEN / ALERT_CHAT_ID. Базовый HTTPS-адрес задаётся ALERT_API_ROOT (по умолчанию https://api.telegram.org); для прокси укажи адрес Worker, при необходимости с префиксом пути. Сервис сам добавит /bot<TOKEN>/sendMessage; токен и метод в ALERT_API_ROOT не включать. До включения формы настроить и проверить канал. В уведомлении только внутренний ID и код проблемы.
Доставленные заявки удаляются через 30 дней; недоставленные автоматически не удаляются, администратор разбирает их отдельно. Срок резервных копий согласовать отдельно.
